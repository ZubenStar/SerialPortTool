# 串口工具 (SerialPort Tool)

> **多串口实时监控 / 调试工具** — 基于 WinUI 3 与 .NET 9 构建的 Windows 桌面串口助手。

SerialPortTool 面向需要同时盯多个串口的调试与产线场景：多口并发收发、实时日志筛选、波特率不匹配自动识别，以及（可选开启的）通过串口批量推送 tuning / TOTA 固件包。

---

## ✨ 功能特性

- **多串口并发管理**：扫描、逐个打开/关闭、一键「打开全部 / 关闭全部」，每个串口独立收发与统计。关闭是彻底的：关闭时若正赶上自动重连，或正有一次波特率检测占用该串口，关闭操作都会优先生效（检测会被取消），不会出现「关掉了但串口仍被占用、只能退出程序才能释放」的情况。
- **灵活串口配置**：波特率（含自定义，可输入 1 ~ 12000000 之间的整数）、数据位、停止位（1 / 1.5 / 2）、校验位（无 / 奇 / 偶 / 标记 / 空格）、流控（无 / 软件 XON-XOFF / 硬件 RTS-CTS / 两者）。左侧配置栏常显「配置档案」与「波特率」，其余参数收在**「高级参数」折叠区**里（默认收起，展开状态会被记住）——它们是一台设备配一次就不再动的，折叠时标题上的 `8-N-1` 摘要会告诉你「下次打开串口」将采用什么线路参数（流控与编码只在与默认值不同时才追加列出，例如 `8-N-1 · 硬件 RTS/CTS`）。五项参数都会被记住，重启后保持上次选择；它们在串口**打开时**生效，所以已有串口打开时改动下拉框会在状态栏明确提示「对下次打开生效」，关闭并重新打开该串口后即按新参数工作。若选了 1.5 停止位而打开失败，提示会额外说明该参数可能不被设备或驱动支持，建议改回 1 或 2。配置持久化到 `settings.json`（原子写入，读取失败时自动进入只读保护，绝不覆盖原文件）。
- **配置档案（预设）**：把当前的串口参数连同**行尾符**一起存成一个有名字的档案，之后一键套用。适合在一台经常要切换不同设备（不同波特率 / 校验方式 / 行尾）的机器上省掉反复调参。套用只写回到左侧配置栏，也就是「下次打开时用这套参数」——这与其它串口参数的规则一致：打开着的串口不会被悄悄关闭重开。最多保存 12 套，随 `settings.json` 保存。**行尾符是档案的一部分**，因为只改波特率却保留旧的行尾符会造成「看着套用了、发出的帧还是错的」这种最难受的结果。
- **串口设备信息**：可用串口列表在每个 `COMx` 下面会补一行设备身份（厂商 / 描述 / VID:PID），这些来自 PnP 设备节点，**只查询不打开**——打开会占用串口句柄，正是由它列出来的这些口随后反而打不开。查不到就只显示端口名（板载串口、虚拟串口常常没有 USB 信息），不会因此影响扫描。
- **端口备注 / 标签 / 分组**：给任意端口写一句备注、打几个标签、归到一个分组里，这些信息会显示在端口列表的这一行下方，也能被 F2 命令面板搜到——下次面对一堆 `COM7` `COM12` 时不必再逐个打开确认哪台是哪台。备注是**纯本地元数据**：不会发出去、不会写进该串口的文件日志、不会出现在导出里。清空所有字段即等于删除这条备注，不会留下空条目。
- **打开后自动发送初始化序列（默认关闭）**：勾选后，串口打开成功会自动发送一段预设内容（多行则逐行发送，支持与快捷指令相同的 `${date}` / `\r` 等变量）。**默认关闭**，因为它会向一个你还没来得及看的设备主动写入内容——不少 bootloader 与配置台在启动的头一秒收到意外指令会直接切换模式，所以这不是「多发一行无害」，而是「设备不再做原来的事了」。每次打开只发一次：自动重连不会重发，「全部打开」也不会触发。**恢复上次打开的串口**同样不会发送任何东西。
- **启动时恢复上次打开的串口（默认关闭）**：勾选并重启后，程序会按上次记住的参数重新打开这些串口；已经拔掉的设备会被跳过并在状态栏说明，不会卡住启动。**默认关闭**：启动时就去占用 COM 会和别的程序（或同机的另一个使用者）抢端口，产线设备被意外占用远比「少点一次」严重。
- **文本编码（UTF-8 / GB18030）**：接收数据的解码方式可按串口选择，GB18030 模组的**中文日志不再显示为乱码**；每个串口各自记住自己的编码（关闭重开后恢复），改动对已打开的串口**即时生效**、无需重开。注意「文件日志」与「导出」始终是 UTF-8 无 BOM —— 写进去的是已经解码好的文本，所以换编码不会改变日志文件的格式。
- **单实例运行**：同一时间只允许一个实例。重复启动会直接给出提示并退出，避免两个实例争抢同一个串口、以及相互覆盖设置文件。
- **外观切换**：菜单「外观」可选 **跟随系统 / 浅色 / 深色**，切换即时生效并会被记住；两套配色各自校准（含端口标识色），标题栏使用云母材质（系统不支持时自动降级为实色）。切换时有一次很短的颜色过渡而不是瞬间跳变（在 Windows 关闭「动画效果」时自动跳过）；启动时直接以保存的配色绘制第一帧，不会闪白。
- **可折叠配置栏**：左侧串口配置与端口列表可一键折叠，窗口变窄时会自动收起，把宽度让给日志；内容超出窗口高度时整栏可滚动，所以窗口再矮也够得着底部的「已打开串口」。
- **波特率不匹配检测**：实时分析数据质量，识别错的波特率并给出高置信度修正建议（一键修正）。
- **实时日志系统**：
  - 关键字 / 正则表达式筛选，可切换 **文本 / 正则** 与 **区分大小写**（默认文本模式，`(` `[` `*` 等字符按字面匹配，不会报错）；**回车或点「搜索」才执行过滤**，输入过程中不刷新日志；搜索历史收在「历史」按钮的浮出面板里（可单条删除、可一键清空），两个开关会被记住。
  - 暂停日志追加（不中断串口接收）、清空日志。
  - 日志区鼠标滚轮按「约五分之一屏」滚动（每格约 3~4 行），并带惯性缓动——一格是短促滑过去而不是整屏瞬跳，连续快滚与触控板细粒度滚动都不会丢位移；滚轮只影响日志区，键盘翻页与拖动滚动条行为不变。
  - **跟随最新 / 回看历史**：默认贴着最新一行走；只要把视图往上滚（滚轮、拖动滚动条、键盘都算）就自动脱离跟随，新数据继续写入但**不再把视图拽回底部**，右下角出现「回到最新」按钮，点一下或滚回底部即恢复跟随——不必为了回看几行而先暂停接收。回看期间日志缓冲区暂停裁剪，避免行被抽走导致内容跳动。
  - **高吞吐下自动降级**：当数据量远超视图的呈现能力时（100 ms 内超过 150 行或 16 KB，或出现一行超过 4096 字符却迟迟没有换行），状态栏与通道图例上的统计数字会暂时停止刷新；同时日志刷新从约 20 次/秒改为约 7 次/秒、每次批量更大——每秒呈现的行数不变，但整屏重建次数降到约三分之一，UI 线程因此有余力处理滚动与输入。洪峰过去后自动恢复并补齐到准确值。**日志内容、落盘文件、筛选与裁剪完全不受影响**，只是统计数字在洪峰期间不再跳动。
  - 每个串口独立 RX 颜色 + 可配置 TX 颜色，便于多口对读；日志区支持 `Ctrl+C` 复制、`Ctrl+A` 全选与右键菜单；复制结果会在右下角给出提示——成功会自行消失，**失败会一直留着直到手动关闭**（"剪贴板里没有内容"是这类失败唯一的证据，放在状态栏里容易被忽略）。
  - 每行日志左侧带一条所属串口的「通道色条」，日志上方另有「通道图例」列出 颜色 → 端口 → 收发字节数，多口交织时一眼分清每行的归属。
- **Tuning / TOTA 推送（隐藏功能，默认关闭）**：需先在「工具 → 启用 Tuning 功能」中勾选（状态会记住），工具条才会出现 Tuning 面板；选择 `.bin` 载荷与自备的 JSON 协议描述文件后广播到所有已打开串口，支持监听文件变化自动重发。取消勾选会隐藏面板并停止自动监听，但已保存的 `.bin` / JSON 路径与监听偏好都会保留。
- **数据发送**：文本 / 十六进制模式（十六进制支持空格 / `-` / `,` / `:` 等分隔符与每组可选的 `0x` 前缀），回车或点「发送」即可广播到全部已打开串口。这些发送选项（十六进制、显示发送数据、TX 颜色、行尾、多行拆分、行间隔）都收在发送行左侧的 **「发送设置」浮出面板**里，发送输入框与「发送」按钮因此始终留在原地——窗口再窄也只会压缩输入框，不会把它们挤掉。文本模式可选 **行尾**（无 / `CR` / `LF` / `CRLF`，默认「无」——发送框里的内容原样发出）；选中行尾符后可勾选 **多行拆分**，让输入里的换行逐行发送、每行各带一个行尾符，不勾选则整段内容末尾只加一个。多行发送时日志每行一条（超过 20 行只逐行显示前 20 条，并注明其余行同样已发送）。勾了「多行拆分」后还能设 **行间隔**（毫秒）：逐行发送时行与行之间等待一段时间，喂那些处理不过来连续命令的设备（例如烧录或配置脚本）。默认 `0`，即整段一次发出——没设过行间隔时发出的字节与以往完全一致。文本按**各串口各自的编码**编码，所以向配置了不同编码的多个串口广播同一条内容是安全的；十六进制模式不受行尾符影响。
- **发送历史**：在发送框里按 **↑** 召回最近发送过的内容（最多 10 条，随设置保存），按 **↓** 回到更新的一条，走过最新一条会恢复开始召回前输入的内容。重复发送同一条只是把它移到最前，不会产生重复项；重新编辑输入框会结束这次召回。十六进制内容按原样记入历史，召回后仍由「十六进制发送」开关决定如何解释。点发送行的「发送历史」图标（悬停显示完整说明）会打开一个可搜索、可逐条删除的面板：`Enter` 或单击把一条填回发送框，行尾的回收站图标删除这一条，右下角可一键清空。**它和 ↑/↓ 读的是同一份数据**，所以在面板里删掉的内容 ↑ 也不会再召回；搜索按词匹配、忽略大小写与标点，和 F2 命令面板是同一套排序。
- **发送目标**：发送行的「目标」可把本次发送限定到部分已打开串口（默认「全部」，逐个勾选）。该范围同时作用于发送框、快捷指令与 F2 命令面板；按钮上始终显示当前范围，部分发送时状态栏也会点名实际目标——避免「以为在广播、其实只发了一个口」。范围只在本次运行内有效，被选中的串口关闭后会自动移除，全部移除即回到「全部」。**Tuning 推送不受它影响**，仍然广播到所有已打开串口。
- **连接事件进日志**：打开、关闭、断开、重连与端口错误都会作为一条 `[SYS]` 行写进日志，与数据行按时间先后交错排列，并**同时写入该串口的文件日志**——所以「这几秒为什么没有数据」和「凌晨三点这个口为什么断了」都能直接从日志里查到，不必去翻程序运行日志。事件行用弱化的中性灰显示，与端口颜色区分开。错误风暴不会淹没数据：同一条错误在 1 秒内重复时折叠成一条带次数的汇总行（例如「重复 17 次」），而断开/重连这类状态变化无论多频繁都逐条记录。
- **日志字号**：在日志区按住 **Ctrl 滚动滚轮**即可放大/缩小，**`Ctrl` + `+` / `-`** 同样可以，**`Ctrl` + `0`** 恢复默认；「外观 → 日志字号」菜单里也有这三项。字号会被记住（范围 10 ~ 24），重启后保持。日志区的滚轮步长与「贴底」判定会跟随字号，所以放大文字不会让滚轮变弱。
- **快捷指令库**：把常用内容存成带**名称与分组**的指令，在发送框旁的「快捷」图标（悬停显示完整说明）里一键广播到全部已打开串口。指令可标记为十六进制，也可开启变量解释（`${date}` / `${time}` / `${datetime}` / `${epoch}` / `${epochms}` 与 `\r` `\n` `\t` 转义；**未识别的写法原样发送**，不会吞掉你输入的字面内容）。库随 `settings.json` 一起保存，重启与升级都不会丢；每条可单独删除。
- **命令面板（F2）**：按 **F2** 打开一个纯键盘的快速切换器，一次搜两样东西 —— **串口**（已打开的会带上它的标识色与收发量，可直接打开/关闭）和**快捷指令**（按名字、分组或**内容**都能搜到，回车即广播发送）。输入即筛选：多词查询**按词逐条命中、顺序无关**，并忽略连字符与标点 —— `prod api` 与 `prodapi` 都能找到 `prod-api-01`，中文也不必和空格、标点严丝合缝；结果按「标题开头 > 标题包含 > 关键字包含」排序，所以被你点名的那条会排在最前，不会被列表里的其它条目挤掉。`↑↓` 选择、`Enter` 执行、`Esc` 或点暗处关闭；再按一次 F2 也能收起。用功能键而不是 `Ctrl+K` 之类，是因为中文输入法下字母组合键经常被输入法或常驻工具吃掉。注意它不复制任何数据：指令与串口都直接取自界面上的同一份来源，所以在别处删掉的指令，重新打开面板就没了。
- **关键字高亮**：在搜索框旁的「高亮」里添加规则（纯文本或正则、可选区分大小写、颜色取自与端口标识同一套色板），命中的文字会在日志里染上该颜色，方便一眼扫出 `ERROR` / `TIMEOUT` 之类。规则随 `settings.json` 保存，可逐条启用/停用/删除。高亮属于「装饰」：**数据洪水期间会自动暂停、洪峰过后自动恢复**，日志内容、落盘文件与筛选完全不受影响；添加时无法生效的正则会当场被拒绝，而不是默默什么都不做。
- **导出日志**：工具栏的导出按钮把**屏幕上看到的内容**存成 `.txt`——有选中行时只导出选中行，没有选中时导出当前整个（已筛选/已搜索的）视图。文件正文与行内容逐字节一致，前面加一段 `#` 开头的头部，记下导出时间、范围、行数、搜索框内容与编码（UTF-8 无 BOM，方便直接 grep 或喂给脚本）。快照在打开选择器之前就取好，所以导出的永远是**同一个瞬间**的日志，而不是选择文件期间又涌进来的数据。注意这与「文件日志」是两件事：文件日志按原样记录全部到达的数据，导出记录的是你正在看的那一部分。
- **日志落盘**：串口日志异步批量写盘；除设备数据外，该端口的连接事件（打开 / 关闭 / 断开 / 重连 / 错误）也会写进同一个文件，标记为 `SYS`，便于事后排查（注意：**发送出去的内容不写入这个文件**，文件记录的是"收到了什么 + 这个端口上发生了什么"）。应用运行日志（Serilog）可在「工具 → 打开日志文件夹」直接定位，或随时按 `F9` 打开。
- **检查更新 / 自动更新**：每次启动都会在后台静默检查 GitHub Releases（发现新版本后本地记住、不再重复联网；没有待处理更新时两次检查至少间隔 30 分钟，程序持续运行时每 24 小时再补查一次），有新版本时提示并可下载安装；「帮助 → 检查更新」可随时手动检查。
- **现代化界面**：Fluent Design + 云母材质标题栏，深浅两套配色（另含高对比主题），统一的字形图标与控件样式，统一的卡片/面板外观，日志列表虚拟化，可跑高吞吐数据流；尚未打开串口时日志区会给出「怎么开始」的引导提示，而不是一片空白。

## 📥 安装与更新

发布产物有两种，都是自包含的，无需另外安装运行时：

| 方式 | 文件 | 说明 |
| --- | --- | --- |
| **安装程序（推荐）** | `SerialPortTool-Setup-v<版本>-win-x64.exe` | 单个文件，安装到 `%LOCALAPPDATA%\Programs\SerialPortTool`。**当前用户级安装，无需管理员权限，不弹 UAC**；创建开始菜单快捷方式，可选桌面快捷方式；可从系统「应用和功能」卸载。 |
| **便携版** | `SerialPortTool-v<版本>-win-x64.zip` | 解压到任意目录，直接运行 `SerialPortTool.exe`，不写注册表。 |

卸载只清理程序文件，**保留**用户设置（`%LOCALAPPDATA%\SerialPortTool\settings.json`）与运行日志。

### 检查更新

- **待处理更新会记住**：一次检查发现新版本后，结果就存在本地了——之后每次启动直接读它并立刻提示，**不再重复联网**（点「稍后」后重启程序，仍是马上就看到提示，不会因为节流窗口而静默）。这个缓存有三种失效方式：你点了「跳过此版本」、你已经装上了那个版本（此后再联网找更新的版本），或者它已经超过 **24 小时**——超过一天就重新联网确认一次，以免一直提示一个已经过时或已被撤回的版本。
- **启动静默检查**：每次启动后数秒都会在后台检查一次，只有发现新版本才会提示；**没有**待处理更新时，两次成功的静默检查之间至少间隔 30 分钟（反复启动不会反复请求），因此新版本最坏在发布后半小时内被发现——不会出现「距上次检查不足 24 小时就不查」那种长达一天的延迟。
- **运行期检查**：程序持续运行时每 24 小时自动补查一次，长时间挂机也能收到新版本提示。
- **检查失败退避**：断网、请求超时或被 GitHub 限流后的 1 小时内不再重试（避免请求风暴）；网络恢复后最多 1 小时即可重新发现更新。
- **手动检查**：「帮助 → 检查更新」随时触发，始终立即联网（不受上述间隔与退避影响），无论结果如何都会给出明确反馈；手动检查也不会改变后续静默检查的节奏。若看到「更新检查过于频繁（GitHub 接口限流）」，说明本机（或所在网络的公网 IP）在一小时内请求 GitHub 接口过多，稍后重试即可。
- **更新对话框**（安装版）：可「下载并安装」，或「跳过此版本」（静默检查时）/「前往下载页」（手动检查时），或「稍后 / 关闭」。「稍后」只是本次不再处理，提示会一直保留到新版本装好或被跳过为止。
- **更新对话框**（便携版）：只能「前往下载页」（静默检查时还可「跳过此版本」）。
- **自动替换**：仅在**安装程序安装的版本**上生效——下载并校验安装包后，程序自动退出、由安装程序静默替换文件并自动重启，用户设置与日志不会丢失。
- **便携版**：不会自动替换任何文件，只会提示并打开下载页（避免覆盖你自己的解压目录）。

## 🚀 快速开始

### 前置要求

1. **Windows 10 1809（build 17763）及以上**，推荐 Windows 11。
2. **.NET 9 SDK**（`dotnet --version` 显示 `9.0.x`）。
3. **Visual Studio 2022 17.8+**（使用 IDE 时），需要工作负载：`.NET 桌面开发`、`通用 Windows 平台开发`、`Windows 应用开发`。
4. Windows App SDK 1.6 运行环境 / 构建工具（通过 NuGet 还原自动获取）。

### 构建与运行

**Visual Studio**：打开 `SerialPortTool.sln` → 还原 NuGet 包 → `Ctrl+Shift+B` 构建 → `F5` 调试。

**命令行（PowerShell）**：

```powershell
dotnet restore
dotnet build --configuration Release
dotnet run

# 发布自包含版本（与发布流水线一致的参数）
dotnet publish --configuration Release --runtime win-x64 --self-contained true `
  --output publish/x64 -p:PublishTrimmed=false -p:PublishReadyToRun=false -p:PublishSingleFile=false

# 打包成本地安装程序（需要 Inno Setup 6，产物输出到 packages/installer）
.\scripts\build-installer.ps1
```

> 构建过程会调用 `scripts/` 下的 PowerShell 脚本，因此必须在 Windows 上构建。

### 基本使用

1. 「工具 → 扫描串口」，在左侧「可用串口」中选择并打开（可多选并发），或直接点「全部打开」。
2. （可选）Tuning 推送默认关闭：先在「工具 → 启用 Tuning 功能」勾选，工具条第二行才会出现 Tuning 面板；选择 tuning `.bin` 与协议 JSON，点「发送 Tuning」即在所有已打开串口上广播。再次取消勾选即隐藏面板并停止自动监听（已保存的路径与监听偏好保留）。
3. 底部输入框输入内容后按 **回车**（或点「发送」）发送到全部已打开串口；在发送行左侧的「发送设置」里勾选「十六进制发送」可发送 hex 字节。若设备需要以回车结束，在同一面板里把「行尾」选成 `CR`（需要时可再勾「多行拆分」让多行内容逐行发送，旁边还能设「行间隔」）；按 **↑** 可召回最近发送过的内容，或点发送行的「发送历史」图标打开可搜索的完整列表。
4. 经常切换不同设备时，在左侧「配置档案」里把当前参数存成一套有名字的档案，之后选它点「套用」即可；数据位 / 停止位 / 校验位 / 流控 / 编码收在下面的「高级参数」折叠区里，展开即可调整（收起时标题上的 `8-N-1` 摘要就是当前值）。先看要经过哪台设备时，用可用串口下的「端口备注」给端口写一句话。点发送行的「快捷」图标可把当前内容存成带分组与名称的快捷指令，之后一键发送（详见「快捷指令库」）。
4. 日志区搜索框输入关键字后按 **回车**（或点「搜索」）过滤——输入过程中不会改动日志；`.*` 是正则开关（默认关闭，此时按字面匹配），`Aa` 是区分大小写开关，两者都会被记住；点输入框右侧的 ✕ 立即清空搜索并恢复全部日志；点「历史」从浮出面板里复用或删除最近 5 条搜索。工具条右侧为 全选 / 复制 / 清空 / 暂停，`Ctrl+C` 复制选中行、`Ctrl+A` 全选。
5. 出现「检测到波特率可能不匹配」提示时，可直接一键修正。
6. 需要更大的日志区时，点标题栏右侧的折叠按钮（或「工具 → 折叠 / 展开串口配置栏」）收起左侧配置栏；配置栏内容超过窗口高度时可以整栏滚动，底部的「已打开串口」不会被截断。
7. 换配色走菜单「外观 → 跟随系统 / 浅色 / 深色」，切换即时生效，重启后保持上次选择。
8. 键盘快捷键：**`F9`** 打开日志文件夹（等同于「工具 → 打开日志文件夹」，焦点在搜索框或发送框内同样有效）；**`F2`** 打开 / 收起命令面板；日志区 **`Ctrl+C`** 复制选中行、**`Ctrl+A`** 全选、**`Ctrl` + 滚轮** 缩放日志字号（也可用 **`Ctrl` + `+` / `-`**，**`Ctrl` + `0`** 恢复默认）；搜索框内按 **回车** 执行搜索；发送框内按 **回车** 发送、按 **↑ / ↓** 在发送历史里前后翻找。

## 📦 版本与发布

- 版本号与更新日志的**唯一来源**是 `version.json`，构建时自动同步到程序集信息与 `Package.appxmanifest`。
- 本地升版本：编辑 `version.json`，或执行
  ```powershell
  .\scripts\bump-version.ps1 -BumpType patch
  ```
- 正式发布：推送 `v*` 形式的 tag（如 `v2.0.0`），GitHub Actions 会校验 `version.json` 与 tag 一致后自动构建 x64 自包含产物并创建 Release，同时上传 **单文件安装程序 Setup.exe** 与**便携 ZIP**。

## 🗂️ 运行数据位置

| 内容 | 位置 |
| --- | --- |
| 应用运行日志（Serilog） | `%USERPROFILE%\Documents\SerialPortTool\DebugLogs\app-<date>.log`（按天滚动，保留 7 天，单文件上限 50 MB） |
| 用户设置 | `%LOCALAPPDATA%\SerialPortTool\settings.json`（由 `SettingsService` 管理：写入带文件锁且为同目录临时文件 + 原子替换；若该文件无法解析则本次运行只读，不会覆盖原文件） |
| 更新下载临时目录 | `%TEMP%\SerialPortTool\Update\`（安装包下载落地点，启动时自动清理历史残留） |
| 安装位置（安装版） | `%LOCALAPPDATA%\Programs\SerialPortTool`（每用户安装，不需要管理员权限） |

本版新增的用户设置（同样落在 `settings.json`，可手工编辑，值不合法时按各自的兜底值处理而不是拒绝启动）：

| 设置键 | 说明 | 默认 |
| --- | --- | --- |
| `PortPresets` | 配置档案库（JSON 数组，最多 12 套） | 空 |
| `PortMetadata` | 各串口的备注 / 标签 / 分组（JSON 数组） | 空 |
| `SessionRestoreEnabled` | 启动时恢复上次打开的串口（`0` / `1`） | `0`（关闭） |
| `SessionRestorePorts` | 上次打开的串口及其参数（JSON 对象，键为串口名） | 空 |
| `AutoInitSequenceEnabled` | 打开后自动发送初始化序列（`0` / `1`） | `0`（关闭） |
| `AutoInitSequence` | 初始化序列内容 | 空 |
| `SendLineDelayMs` | 多行发送的行间隔毫秒数（上限 10000） | `0`（整段一次发出） |
